# Safety First

1. Inspect before changing anything. Read relevant files, configuration, package manifests, scripts, tests, and existing patterns before editing.
2. Never erase, reset, revert, force-push, mass-rewrite, or delete user work unless the user explicitly requests that exact destructive operation.
3. Do not modify unrelated files merely to make a change easier.
4. Preserve existing behavior unless the requested change requires behavior changes.
5. Before risky operations, summarize the risk and ask for approval when the operation is destructive, security-sensitive, irreversible, or likely to affect external systems.
6. Never expose, print, commit, or copy secrets, tokens, private keys, cookies, credentials, or sensitive environment values.
7. Never claim success without evidence. Distinguish implemented, tested, observed, and assumed.
8. Prefer small, reversible edits. After a significant change, inspect the diff.
